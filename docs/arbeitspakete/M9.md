# Arbeitspaket M9 – Diagramm-Editor

Siehe konzept-natter.md, Abschnitt 13 (Diagramm-Editor), 14 (Design-
Prüfer, Layout-Hinweise gelten sinngemäß). Kleinteilig wie M1–M8.

## Abnahmekriterium (aus dem Konzept)

UML-Klassendiagramm `TAmpel`, Struktogramm `ampel_zeichnen` und
Entscheidungstabelle der Ampel von Hand erstellen und als PDF
exportieren.

## Reihenfolge (Nutzer-Feedback September 2026)

Erst die MVP-Dreiergruppe aus dem Abnahmekriterium fertig und
abgenommen (Klassendiagramm, Struktogramm, Entscheidungstabelle),
danach Use-Case-, Aktivitäts-, Zustands- und Sequenzdiagramm als eigene
Schritte (Abschnitt 13.4: „Später“). Innerhalb der Dreiergruppe zuerst
das Fenster-Grundgerüst und das `.pdiag`-Format (beide werden von allen
drei gebraucht), dann das Klassendiagramm komplett (Formen → Bearbeiten
→ Verbindungen → Beschriften → Eigenschaften-Panel → Stilvorlagen/
Layout-Hinweise → Export/Druck – dieselbe Reihenfolge wie beim Designer
in M3: Anzeige vor Bearbeiten vor Verbindungen), zuletzt Struktogramm
und Entscheidungstabelle (strukturell näher an einer Baumstruktur bzw.
`StringGrid` als an Formen+Verbindungen, deshalb eigene Schritte statt
Wiederverwendung der Klassendiagramm-Canvas).

Fenster-Architektur (Nutzer-Feedback bestätigt): echtes zweites
Top-Level-Fenster mit eigenem Taskleisten-Eintrag, unabhängig vom
Hauptfenster verschiebbar (Abschnitt 13.1) – kein Dock/Tab in der IDE.

Export-Umfang (Nutzer-Feedback bestätigt): PNG, SVG, PDF und Drucken
gehören von Anfang an zum ersten fertigen Diagrammtyp, nicht erst
später nachgezogen.

### 1. `.pdiag`-Datenmodell und Fenster-Grundgerüst

- [ ] `schemas/pdiag.schema.json` ist als Entwurf bereits vorhanden
  (M0) – gegen die drei MVP-Typen (`class`, `struktogramm`,
  `entscheidungstabelle`) prüfen/erweitern, insbesondere die Blockbaum-
  Struktur für Struktogramme und die Tabellenstruktur für
  Entscheidungstabellen fehlen dort noch (nur `shapes`/`connectors`
  für Formen-Diagramme sind entworfen)
- [ ] `ide/diagramm/datei.py` (Name offen): `.pdiag` laden/speichern,
  Validierung gegen das Schema, analog zu `ide/project/projekt.py`
- [ ] `ide/diagramm/fenster.py`: eigenes `QMainWindow` (nicht
  `QDialog`), eigener Taskleisten-Eintrag, Menüleiste nach Abschnitt
  13.2 (Datei/Bearbeiten/Ansicht/Anordnen/Format/Hilfe – vorerst nur
  die für die MVP-Dreiergruppe sinnvollen Einträge aktiv, Rest
  ausgegraut statt vorzutäuschen), Statusleiste (Auswahl/Raster/
  Einrasten/Seitenformat/Stilvorlage)
- [ ] `.pdiag`-Dateien im Ordner `diagramme/` erscheinen im Projekt-
  Explorer (wie `.pfm` für Formulare), Doppelklick öffnet das
  Diagramm-Fenster statt eines Editor-Tabs
- [ ] „Datei → Neu“ fragt den Diagrammtyp ab (vorerst nur die drei
  MVP-Typen zur Auswahl)
- [ ] Tests: Laden/Speichern round-trip, Schema-Validierung lehnt
  ungültige Dateien ab, Fenster lässt sich unabhängig vom Hauptfenster
  öffnen/schließen, Explorer-Doppelklick öffnet das richtige Fenster

### 2. Klassendiagramm: Formen anzeigen und platzieren

- [ ] Formen-Palette (links, Abschnitt 13.2) für den Diagrammtyp
  „Klasse“: Klasse, abstrakte Klasse, Interface, Notiz, Paket –
  gleiches Interaktionsmuster wie die Komponentenpalette (M3, Klick
  macht scharf + Klick auf die Fläche platziert dort, siehe
  `ide/designer/canvas.py`, `platzierungsmodus_setzen`)
- [ ] Zeichenfläche zeichnet platzierte Formen als eigene, minimal
  gestylte Widgets oder direkt per `QPainter` (Entscheidung hier
  treffen – bei sehr vielen Formen ist Canvas-Zeichnen vermutlich
  performanter als ein Widget pro Form, anders als beim Designer mit
  wenigen Steuerelementen)
- [ ] Raster + Lineale + Minimap (Abschnitt 13.2), Zoom (Strg+Mausrad,
  Strg+0, Strg+1), Verschieben der Ansicht (Leertaste+Ziehen)
- [ ] Tests: Form platzieren erzeugt den richtigen Eintrag im
  Datenmodell, Zoom-Stufen, Rasteranzeige an/aus

### 3. Klassendiagramm: Auswählen, Verschieben, Größe, Löschen, Duplizieren, Undo

- [ ] Auswahl (Einzel-/Mehrfachauswahl per Rahmen/Strg+Klick),
  Anfasser zur Größenänderung, Einrasten am Raster UND an Kanten/
  Mitten anderer Formen mit Hilfslinien (Abschnitt 13.3 – über das
  reine Rasterschritt-Einrasten des Designers hinaus, dort gab es
  keine Formen-zu-Formen-Hilfslinien)
- [ ] Verschieben/Größe per Tastatur (Pfeiltasten/Alt/Umschalt, wie
  Designer), Entf löscht, Strg+D dupliziert
- [ ] Ausrichten/Verteilen/Gleiche Größe/Vordergrund-Hintergrund/
  Gruppieren (Strg+G/Strg+Umschalt+G) – im Designer (M3) nicht nötig,
  hier neu
- [ ] Kommando-Muster wie `ide/designer/kommando.py` für Rückgängig/
  Wiederholen (unbegrenzt innerhalb der Sitzung, Abschnitt 13.3)
- [ ] Tests: jede Operation einzeln, Undo/Redo-Kette, Ausrichten mit
  mind. 3 Formen ergibt die erwarteten Koordinaten

### 4. Klassendiagramm: Verbindungen

- [ ] Verbindungstypen: Assoziation, gerichtete Assoziation,
  Aggregation ◇, Komposition ◆, Vererbung ▷, Abhängigkeit,
  Realisierung (Abschnitt 13.4) – je eigene Pfeilspitzen-/
  Linien-Darstellung nach UML-Norm (Abschnitt 13.6)
- [ ] Verbindung ziehen (Form zu Form), Andockpunkte, die beim
  Verschieben der verbundenen Form folgen
- [ ] Linienführung gerade/rechtwinklig/mit Knickpunkten
  (Doppelklick fügt/entfernt einen Knickpunkt)
- [ ] Multiplizitäten und Rollen an Verbindungsenden, frei
  verschiebbar, bleiben an der Linie
- [ ] Tests: Verbindung folgt beim Verschieben einer Form, Knickpunkt
  hinzufügen/entfernen, jede Verbindungsart wird korrekt gespeichert/
  geladen

### 5. Klassendiagramm: Beschriften

- [ ] Doppelklick auf eine Form bearbeitet Name/Attribute/Methoden
  direkt inline; Tab springt zum nächsten Textfeld
- [ ] Kurzeingabe für Attribute/Methoden: eine Zeile pro Eintrag,
  Sichtbarkeitspräfix `+`/`-`/`#`, Enter fügt eine Zeile hinzu,
  Strg+Pfeil sortiert um (Abschnitt 13.4) – kein Prüfen auf
  syntaktische Richtigkeit
  Abstrakte Klasse: `{abstract}`-Kennzeichnung, kursiver Name
- [ ] Tests: Zeile hinzufügen/entfernen/umsortieren, Sichtbarkeits-
  präfix wird korrekt dargestellt, abstrakte Klasse kursiv/markiert

### 6. Eigenschaften-Panel

- [ ] `ide/diagramm/eigenschaften_panel.py` (Name offen), rechts im
  Fenster (Abschnitt 13.2): Füllung, Linie, Schrift, Größe/Position
  der ausgewählten Form bzw. Verbindungs-Beschriftungen – strukturell
  wie `EigenschaftenTabelle` aus M3, aber eigenständig (Diagramm-
  Formen sind keine `pcl.Control`-Komponenten)
- [ ] „Format → Stil übertragen“ (Format einer Form auf eine andere
  übernehmen)
- [ ] Tests: Eigenschaft ändern wirkt sofort auf die Form, Stil
  übertragen kopiert Füllung/Linie/Schrift korrekt

### 7. Stilvorlagen und Layout-Hinweise

- [ ] Drei Stilvorlagen (Modern hell/Modern dunkel/Schwarz-Weiß,
  Abschnitt 13.6), für das ganze Diagramm umschaltbar, unabhängig vom
  IDE-Theme; Export verwendet immer die im Diagramm gewählte Vorlage
- [ ] Layout-Hinweise (keine Inhaltsprüfung, nur Darstellung,
  abschaltbar wie beim Design-Prüfer, M7): überlappende Formen,
  abgeschnittene Texte, lose Verbindungsenden, Formen außerhalb des
  Seitenbereichs
- [ ] Tests: jede Stilvorlage rendert mit den richtigen Farben,
  jede Layout-Hinweis-Regel erkennt ihr Testdiagramm (Muster wie
  `tests/test_design_pruefer_regeln.py` aus M7)

### 8. Export und Drucken

- [ ] PNG-Export mit wählbarer Auflösung, transparenter oder weißer
  Hintergrund
- [ ] SVG-Export (`QSvgGenerator`, PySide6 – keine neue Abhängigkeit)
- [ ] PDF-Export (`QPrinter`/`QPdfWriter`, PySide6 – keine neue
  Abhängigkeit)
- [ ] Kopieren in die Zwischenablage (zum Einfügen in Word o. Ä.)
- [ ] Drucken mit Seitenvorschau, Anpassen an Seite (A4/A3, hoch/quer,
  Abschnitt 13.2)
- [ ] Tests: jedes Exportformat erzeugt eine gültige, nicht leere
  Datei mit den erwarteten Abmessungen; PDF-Export eines Test-
  diagramms lässt sich mit einer PDF-Bibliothek zurücklesen und die
  Seitenzahl/-größe prüfen

### 9. Struktogramm-Editor

- [ ] Eigenes Datenmodell: Blockbaum statt Formen/Koordinaten
  (Abschnitt 13.5, 13.7 – `.pdiag` speichert hier keine `shapes`/
  `connectors`)
- [ ] Blocktypen: Anweisung, Verzweigung (ja/nein), Mehrfachauswahl,
  Zählschleife, kopfgesteuerte/fußgesteuerte Schleife,
  Unterprogrammaufruf, Aussprung
- [ ] Block aus der Palette auf eine hervorgehobene Einfügelinie
  ziehen (zwischen Blöcken, in einen leeren Zweig/Schleifenkörper);
  Breiten/Höhen passen sich automatisch an, damit der Rahmen
  geschlossen bleibt
- [ ] Mehrfachauswahl: Fälle über Plus/Minus am Block hinzufügen/
  entfernen
- [ ] Blöcke mit Inhalt verschieben/kopieren/löschen; Enter fügt eine
  Anweisung darunter ein, Entf löscht den Block (wie im Quelltext-
  editor-Muster aus Abschnitt 8.1, aber auf Blockebene)
- [ ] Kopfzeile mit Name des Struktogramms/Unterprogramms, mehrere
  Struktogramme auf einer Seite möglich
- [ ] Export/Drucken wie Schritt 8 (dieselbe Infrastruktur, anderes
  Zeichnen)
- [ ] Tests: Block einfügen an jeder Einfügestelle, Rahmen bleibt
  geschlossen nach verschachteltem Einfügen, Fall hinzufügen/entfernen
  bei Mehrfachauswahl, Undo/Redo

### 10. Entscheidungstabelle-Editor

- [ ] Eigenes Datenmodell: Tabelle mit Bedingungsteil/Aktionsteil,
  Regeln als Spalten (Abschnitt 13.5, 13.7)
- [ ] Spalten (Regeln) hinzufügen/entfernen/verschieben, Zeilen
  (Bedingungen/Aktionen) hinzufügen/entfernen
- [ ] Zellen durchschalten per Klick: Bedingungsteil `J` → `N` → `*`
  → leer, Aktionsteil `X` → leer
- [ ] Keine automatische Zusammenfassung oder Vollständigkeitsprüfung
  von Regeln (bewusst, wie im Konzept festgehalten)
- [ ] Export/Drucken wie Schritt 8
- [ ] Tests: Zelle durchschalten in beiden Teilen, Spalte/Zeile
  hinzufügen/entfernen/verschieben, Undo/Redo

- [ ] Entscheidungstabelle der Ampel-Zustandslogik von Hand erstellen
- [ ] Alle drei als PDF exportieren, Ergebnis-PDFs öffnen sich

## Danach (Abschnitt 13.4: „Später“)

Jeweils eigener Schritt, baut auf der in Schritt 2–8 gebauten
Formen+Verbindungen-Infrastruktur auf (neue Formen-/Verbindungstypen,
kein neues Canvas-Grundgerüst nötig):

- [ ] Use-Case-Diagramm: Akteur, Anwendungsfall, Systemgrenze, Notiz;
  Assoziation, `<<include>>`, `<<extend>>`, Generalisierung
- [ ] Aktivitätsdiagramm: Start-/Endknoten, Ablaufende, Aktion,
  Entscheidung/Zusammenführung, Gabelung/Vereinigung, Swimlane,
  Objektknoten, Notiz; Kontrollfluss mit Bedingung, Objektfluss
- [ ] Zustandsdiagramm: Start-/Endzustand, Zustand (entry/do/exit),
  zusammengesetzter Zustand, Entscheidung, Notiz; Übergang mit
  `Ereignis [Bedingung] / Aktion`
- [ ] Sequenzdiagramm: Akteur, Lebenslinie, Aktivierungsbalken,
  Zerstörung ✕, kombiniertes Fragment (`alt`, `opt`, `loop`), Notiz;
  synchrone/asynchrone Nachricht, Antwort, Erzeugung
- [ ] Abnahme: für jeden der vier Typen ein einfaches Beispiel aus den
  `referenz/lazarus/`-Projekten von Hand nachbauen
