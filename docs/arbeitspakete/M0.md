# Arbeitspaket M0 – Repository, CI, Schemas, Design-Tokens, Design-Referenz

Siehe konzept-natter.md, Abschnitt 20 (Umsetzungsphasen) und 23 (Voraussetzungen).

## Abnahmekriterium

Alle Prüfungen laufen auf einem Windows-Rechner ohne installiertes Python;
Schema-Tests grün; Design-Referenz freigegeben.

## Erledigt

- Repository angelegt, mit GitHub verbunden
- `pyproject.toml` (Python 3.13, Ruff, pytest)
- `AGENTS.md` mit Beitragsregeln
- `LICENSE` (private Lizenz)
- `.gitignore`
- Schemas: `schemas/pfm.schema.json`, `schemas/project.schema.json` (Entwurf),
  `schemas/pdiag.schema.json`
- `design/tokens.json` (Entwurf)
- Schema-Tests (`tests/test_schemas.py`) gegen die Beispiele aus dem Konzept
- CI (GitHub Actions): Ruff + pytest headless unter Linux
- `docs/PLAN.md` mit konkreter Reihenfolge für M0-Rest und M1-Start
- `prototypes/s1`–`s7`: lauffähiger Code bzw. Skripte für alle sieben
  Machbarkeitsprüfungen (Abschnitt 23.3), inkl. je einer `README.md` mit
  Ausführung und Erfolgskriterium; S4 und S6/Manifest bereits erfolgreich
  gegengetestet (siehe deren README)

## Offen

- `schemas/project.schema.json` gegen das erste echte Beispielprojekt
  (`Ampel`) prüfen, sobald es angelegt wird
- `design/referenz/`: freigegebene Design-Referenz (Hauptfenster hell/dunkel,
  Objektinspektor, Designer, Komponentenpalette, Menü, Debugger,
  Fehlermeldung, Diagramm-Editor, Beispiel-Schülerprogramm) – setzt erste
  UI-Mockups voraus, folgt mit M2/M3
- Prototypen S1, S2, S3, S5, S7 auf dem Windows-Laptop tatsächlich
  ausführen und Ergebnis in der jeweiligen `README.md` eintragen (S4 und
  S6/Teil 2 sind bereits gegengetestet, brauchen aber noch eine echte
  Windows-Ausführung zur Bestätigung); bei Durchfallen betroffene
  Technologie-Entscheidung in `konzept-natter.md` anpassen
- Material nach Abschnitt 23.1 (Lazarus-Übungsprojekte, Beispiel-CSVs,
  Beispiel-Datenbank, Beispiel-Diagramme) zusammentragen, siehe
  `docs/PLAN.md`
