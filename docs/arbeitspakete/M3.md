# Arbeitspaket M3 – Designer, Objektinspektor

Siehe konzept-natter.md, Abschnitt 20, 7.6 (Objektinspektor), 7.7
(Designer), 4.3/4.4 (Codegenerierung). Kleinteilig wie M1/M2.

## Abnahmekriterium (aus dem Konzept)

Ampel komplett in der IDE erstellen, alle Eigenschaften nur über den
Inspektor gesetzt.

## Reihenfolge

Objektinspektor zuerst, weil er direkt auf dem bestehenden
`pcl.properties`-Introspektionsmechanismus (`eigenschaften()`/
`ereignisse()`) aufbaut und ohne Designer-Canvas allein schon sinnvoll
und testbar ist. Der Designer (Canvas, Drag&Drop, Undo) danach, dann die
Verbindung beider plus Komponentenpalette, zuletzt die
Ereignis-Codegenerierung (libcst) für Doppelklick → Methode.

### 1. Objektinspektor: Eigenschaften lesen/setzen — erledigt

- [x] `ide/inspector/eigenschaften_tabelle.py`: `EigenschaftenTabelle`
  (Name, Wert) aus `pcl.properties.eigenschaften(typ(komponente))`;
  Zelle bearbeiten → `setattr(komponente, name, wert)` (Live-Wirkung, da
  `Prop.__set__` sofort das Qt-Widget aktualisiert, Abschnitt 5.0)
- [x] Editor je Typ passend zum `Prop.typ`: `bool` → echtes
  Kontrollkästchen (`ItemIsUserCheckable`, nicht editierbarer Text),
  `str`/`int`/`float` → Textfeld mit Typumwandlung beim Verlassen der
  Zelle
- [x] Falscher Wert (z. B. Text in Zahlenfeld) → Umwandlungsfehler bzw.
  `NatterPropertyError` abgefangen, Zelle wird auf den echten
  Komponentenwert zurückgesetzt, `fehlertext`-Attribut gesetzt (Bindung
  an den Hilfebereich folgt mit Schritt 2, sobald der Objektinspektor
  als Ganzes im Hauptfenster eingehängt ist)
- [x] Tests (`tests/test_eigenschaften_tabelle.py`, 6 Tests): Live-
  Bearbeitung ändert Komponente und Qt-Widget gleichermaßen, ungültige
  Zahl wird abgelehnt und zurückgesetzt, Kontrollkästchen für `bool`

### 2. Objektinspektor: Reiter und Komponentenbaum — erledigt

- [x] `ide/inspector/komponentenbaum.py`: `Komponentenbaum` – Wurzel ist
  das Formular, Kinder aus den eigenen Attributen ermittelt, die selbst
  `Control`-Instanzen sind; rekursiv (für künftige Container-
  Komponenten vorbereitet, aktuell mangels Container immer flach)
- [x] `ide/inspector/ereignisse_tabelle.py`: `EreignisseTabelle` – Reiter
  „Ereignisse“ mit Dropdown aus `passende_methoden()` (Formular-Methoden
  mit genau einem Parameter außer `self`, passend zur `(self, sender)`-
  Konvention aus Abschnitt 5.4); Auswahl verknüpft/entfernt den Handler
  live
- [x] `ide/inspector/objektinspektor.py`: `Objektinspektor` verbindet
  Baum + Reiter Eigenschaften/Ereignisse; Auswahlwechsel im Baum
  aktualisiert beide Reiter; in `HauptFenster` an Stelle des
  Platzhalters im Objektinspektor-Dock eingehängt
- [x] Tests: `tests/test_komponentenbaum.py` (3),
  `tests/test_ereignisse_tabelle.py` (6), `tests/test_objektinspektor.py`
  (3, inkl. Baum-Auswahl → Eigenschaft ändern wirkt auf die Komponente),
  `tests/test_hauptfenster.py` (+1)

### 3. Designer-Canvas: Anzeige und Auswahl — erledigt

- [x] `ide/designer/laden.py`: `formular_fuer_designer_laden(pfm_pfad)`
  lädt eine `.pfm` über `ide.codegen.design` und erzeugt eine
  instanziierbare Vorschau-Klasse mit wirkungslosen Platzhaltern für
  referenzierte Ereignis-Handler (Designer braucht keine echte
  Programmlogik, Abschnitt 4.2)
- [x] `ide/designer/canvas.py`: `DesignerCanvas` – Formular und Kinder
  sind echte `pcl`-Widgets (kein Nachbau, Abschnitt 7.7); ein
  `QObject`-Eventfilter fängt echte Mausklicks auf jedem Kind-Widget ab
  (keine echte Interaktion wie ein Button-Klick wird ausgelöst) und
  wählt stattdessen die Komponente aus; Auswahlrahmen über eine
  Qt-Stylesheet-Regel mit dynamischer Eigenschaft (Theme des Formulars
  bleibt dabei unangetastet)
- [x] In `HauptFenster` eingehängt: Doppelklick auf ein Formular im
  Explorer öffnet jetzt den Designer-Tab statt der `.pfm` als Rohtext;
  Klick im Designer aktualisiert den Objektinspektor sofort
  (`Formular/Code umschalten“ aus Abschnitt 7.9 folgt später)
- [x] Tests: `tests/test_designer_canvas.py` (6, inkl. echtem
  `QTest.mouseClick` auf einen Button, der die Auswahl auslöst statt
  `on_click`), `tests/test_designer_laden.py` (3, gegen die echte
  `beispielprojekte/Ampel/u_main.pfm`), `tests/test_hauptfenster_designer.py`
  (4, kompletter Ablauf Explorer-Doppelklick → Designer → Klick →
  Objektinspektor)

### 4. Designer-Canvas: Platzieren, Verschieben, Größe ändern

- [ ] Komponente aus der Palette platzieren (erzeugt Instanz + `.pfm`-
  Eintrag)
- [ ] Ziehen ändert `left`/`top`, Anfasser ändern `width`/`height`,
  Raster-Einrasten
- [ ] Tastatur: Pfeiltasten (Rasterschritt), Alt+Pfeil (1 px),
  Umschalt+Pfeil (Größe), Entf (löschen), Strg+D (duplizieren)
- [ ] Test: Verschieben ändert `.pfm` und Live-Anzeige gleichermaßen

### 5. Undo/Redo (Command-Pattern)

- [ ] jede Designer-Aktion als Kommando mit `tun()`/`rückgängig()`
- [ ] Test: Reihe von Aktionen, vollständig rückgängig machen, Zustand
  identisch zum Ausgangspunkt

### 6. Komponentenpalette

- [ ] Reiter Standard/Zusätzlich (Abschnitt 7.3) mit den bisher
  gebauten `pcl`-Komponenten; Klick+Klick oder Doppelklick platziert
- [ ] Test: Platzieren über die Palette erzeugt die richtige
  Komponentenklasse

### 7. Ereignis-Codegenerierung (libcst)

- [ ] Doppelklick auf eine Komponente im Designer erzeugt
  `def <name>_<ereignis>(self, sender):` in der Formular-Unit (per
  `libcst`, ohne Formatierungsverlust, Abschnitt 4.4) und verknüpft sie
- [ ] Test: generierte Methode kompiliert, Klick im laufenden Formular
  ruft sie auf

### 8. Abnahme: Ampel vollständig in der IDE erstellen

- [ ] Ampel-Formular ausschließlich über Designer + Inspektor + Palette
  nachbauen (nicht die vorhandene `.pfm` von Hand schreiben), Ergebnis
  mit `beispielprojekte/Ampel/` vergleichen

## Zurückgestellt innerhalb M3

- Mehrfachauswahl mit gemeinsamer Eigenschaftsänderung
- Ausrichten/Verteilen-Werkzeuge, Hilfslinien
- Favoriten-Reiter, „Geändert“-Reiter im Inspektor
- Vorschau hell/dunkel und mehrere Fenstergrößen im Designer
