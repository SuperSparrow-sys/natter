# Arbeitspaket M2 – IDE-Grundgerüst

Siehe konzept-natter.md, Abschnitt 20, 7.1–7.5, 7.9. Kleinteilig
aufgeschlüsselt wie M1 in `docs/PLAN.md`. Jeder Schritt einzeln mit
`pytest`/`pytest-qt` headless testbar, wo möglich.

## Abnahmekriterium (aus dem Konzept)

Projekt aus M1 in der IDE öffnen, alle Datei-Menüfunktionen funktionieren,
Projekt `u_pflanzen`/`u_garten` anlegen und starten, Konsolenprogramm mit
`input()` im eigenen Fenster.

## Reihenfolge

Zuerst das, was der Projektinhaber konkret nachgefragt hat (Neues
Projekt/Projekt öffnen) und headless testbar ist; Monaco, die portable
Laufzeit und die "eigenen Fenster" für GUI/Konsole sind Windows-lastig
bzw. laut Abschnitt 21 riskant und kommen später (siehe `prototypes/`).

### 1. Hauptfenster-Grundgerüst (`ide/shell/`)

- [ ] `HauptFenster(QMainWindow)`: leere Menüleiste, Statusleiste, Docks
  für Explorer/Objektinspektor/Panels als Platzhalter (Abschnitt 7.1)
- [ ] Test: Fenster erzeugen headless, Docks vorhanden

### 2. Aktionsregister (`ide/actions/`)

- [ ] `Aktion`: eine Aktion = `QAction` + optionaler Tastenkürzel-Text +
  Kategorie; zentrale `Aktionsregister`-Klasse verwaltet alle Aktionen
  (Grundlage für Menü, Werkzeugleiste und später Befehlspalette, aus
  einer einzigen Definition, Abschnitt 7.2)
- [ ] Test: registrierte Aktion erscheint im zurückgegebenen Register,
  Tastenkürzel-Konflikt wird erkannt

### 3. Projektmodell (`ide/project/`)

- [ ] `Projekt`: lädt/speichert `.natter` gegen
  `schemas/project.schema.json`, kennt Projektordner, Haupt-Unit,
  Liste der Units/Formulare (aus dem Ordnerinhalt ermittelt, nicht nur
  aus der `.natter`, da Units beim Einbinden nicht einzeln eingetragen
  werden, Abschnitt 4.1)
- [ ] Test: `beispielprojekte/Ampel/ampel.natter` laden, Units/Formulare
  korrekt erkannt

### 4. Neu-Dialog: „Neues Projekt …“ (`ide/project/`, `templates/`)

- [ ] `templates/gui/`: Minimalvorlage (`main.py`, leere `u_main.pfm`,
  `<name>.natter`), analog `console/` (Abschnitt 7.5); `gui_db/` später
- [ ] Funktion `projekt_erzeugen(vorlage, zielordner, name)`: kopiert
  Vorlage, ersetzt Platzhalter (Name, Klassenname), erzeugt
  `u_main_design.py` über `ide.codegen.design`
- [ ] Test: neues Projekt erzeugen, mit `python main.py`-Äquivalent
  (Form direkt instanzieren wie in den Abnahmetests) startet es leer

### 5. „Projekt öffnen …“ / „Öffnen …“

- [ ] Aktion „Projekt öffnen …“: `.natter`-Datei wählen → `Projekt.laden()`
  → Projekt-Explorer füllt sich
- [ ] Aktion „Öffnen …“: einzelne Datei öffnen (unabhängig vom Projekt)
- [ ] Test: `beispielprojekte/Ampel` öffnen, Explorer-Inhalt stimmt mit
  den Dateien im Ordner überein

### 6. Projekt-Explorer (`ide/shell/`)

- [ ] Baumansicht: Gruppen Formulare/Units/Assets (Abschnitt 7.4);
  Formular-Units als ein Eintrag, `.pfm`/`_design.py` eingeklappt
  darunter
- [ ] Doppelklick auf eine Datei öffnet sie in einem Editor-Tab
- [ ] Test headless: Baum aus einem geladenen Projekt korrekt aufgebaut

### 7. Editor-Tab (Platzhalter, noch ohne Monaco)

- [ ] einfacher Tab mit `QPlainTextEdit` je offener Datei, `●` bei
  ungespeicherten Änderungen, Speichern (Strg+S)
- [ ] Monaco ersetzt dies in einem eigenen späteren Schritt, sobald S2
  (`prototypes/s2_monaco_jedi/`) auf dem Windows-Laptop bestätigt ist
  (Abschnitt 21: höchstes Risiko im Konzept)
- [ ] Test: Datei öffnen, Inhalt steht im Editor, Änderung + Speichern
  schreibt die Datei

### 8. „Unit öffnen …“ (Schnellauswahl)

- [ ] Strg+P: Liste aller Projektdateien mit Suche (Abschnitt 7.4, 7.9)
- [ ] Test: Filtertext schränkt Liste korrekt ein

## Zurückgestellt innerhalb M2 (folgen, nachdem 1–8 stehen)

- Monaco-Einbindung (ersetzt Schritt 7), Jedi-Vervollständigung, Ruff-
  Markierung im Editor
- vollständiges Menü/Werkzeugleisten-Set aus Abschnitt 7.2/7.3, SVG-
  Symbole
- Units voll (Einbinden-Dialog, Umbenennen mit Importanpassung,
  Kreisbezug-Erkennung, geteilte Ansicht, Tabs anheften/Drag&Drop)
- Sitzung (`.natter-session`): offene Tabs/Cursor/Breakpoints merken
- portable Laufzeit mit getrennten Paketordnern (braucht S1/S4 auf dem
  Windows-Laptop bestätigt)
- Ausführung in eigenen Fenstern (GUI + Konsole) – Konsolenfenster ist
  Windows-spezifisch, hier headless nur eingeschränkt testbar
- Tastenkürzel-Tab, Befehlspalette
- `u_pflanzen`/`u_garten`-Mehr-Unit-Beispielprojekt für die M2-Abnahme
